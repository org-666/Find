## 一、现在能体验的完整流程

| 步骤 | 界面 | 对应模块 |
|---|---|---|
| 1 | 说一句「想找人打羽毛球」→ AI 解析成标签 | B |
| 2 | 「你是想打羽毛球，对吧？」→ 确认 | B |
| 3 | 「正在找附近也想打羽毛球的人…」+ 秒数在跳 | C |
| 4 | 「**有人也想打羽毛球，3 分钟后到附近的羽毛球馆，去吗？**」 | C（AI 替双方做第一轮确认） |
| 5 | 去 / 算了 | D |
| 6 | 点「去」→「正在等对方确认…」→「成了」 | D |
| 7 | 「进临时对话」→ 只有 **我到了 / 我晚点 / 算了** 三个按钮 | E |
| 8 | 90 秒后自动关闭 →「这一局结束了，聊天内容已经清掉了」 | E |

第 3 步点「算了」会回到匹配池并进入第 2 轮；第 5 步点「算了」同样回到池里继续找。

## 二、AI 在这里做什么（严格守着边界）

architecture.md 第七节写死了 AI 的边界，代码里也守着：

- **模块 C**：AI 替双方做第一轮时间地点确认 —— 产出那句「有人也想打羽毛球，3 分钟后到附近的羽毛球馆，去吗？」。
  输入是匹配结果（活动、模糊距离、时段重叠分钟数），输出是地点 + 通勤时间 + 整句话。
- **模块 E**：用户不知道说什么时给**一句方向提示**（如「问问他到哪了」），
  **不替人聊天**——建议必须用户自己点「用这句」才会进输入框，发不发仍由人决定。
  提示语在代码里有硬约束：3-20 字、不含人名和精确位置。

两条 AI 路径都复用了模块 B 那套：配了 key 走真模型，没配 / 超时 / 返回不合法就回退本地规则，永远有结果，界面会标出这次是「AI」还是「本地」。

## 三、试玩模式 vs 真实模式

免登录时对方是**合成的**，但**跑的引擎是真的**：

| | 试玩模式 | 接上数据库后 |
|---|---|---|
| 候选人 | `lib/matching-demo.ts` 合成 4 个（固定偏移表，无随机数） | 从 moments 表查真实需求 |
| 匹配计算 | **同一套** `lib/matching.ts` | 同一套 |
| AI 确认 | **同一套** `lib/ai-confirm.ts` | 同一套 |
| 对方回复 | `demoPeerReplyAction` 按你的话给反应 | 实时通道推真实消息 |
| 一局时长 | 90 秒（为了让你看到它真的会关） | 需求时间窗结束点 |

所以以后接数据，只需要换掉"候选人来源"和"对方回复来源"，引擎、AI、界面都不用动。

## 四、匹配引擎的规则（都有单测覆盖）

```
同活动  +  时段重叠 ≥ 15 分钟  +  距离 ≤ 1.5 公里  →  进候选
打分 = 距离 40% + 时段 35% + 活动 25%
```

- **活动相容**：比的是具体活动名（`打羽毛球` ≠ `打篮球`），只有一边说得很泛（`动一动`/`找个人一起`）时才放宽到"同分类"
- **距离**：Haversine 真算，但**对外只给模糊档位**（200 米内 / 500 米内 / 1 公里内 / 附近），精确坐标任何界面都不会出现——这条有专门的测试断言
- **没有定位**时距离按中位分处理，标签显示「附近」，而不是当成"很远"

## 五、"不留痕迹"是怎么落实的

- 临时对话的消息**只活在浏览器内存里**，服务端一个字都不存（试玩模式）
- 自动关闭 / 手动结束 / 点「算了」三种结束方式，都会立刻清空消息列表并显示「系统没有留任何记录」
- 真实版本对应的是：局结束后物理删除该局的 messages 行，而不是改状态标记
